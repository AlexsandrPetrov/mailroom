# Mailroom control plane

Локальный веб-интерфейс управления почтовым шлюзом. Домены, почтовые ящики, квоты, пользователи и аудит хранятся в PostgreSQL; системные операции остаются в режиме чтения до подключения privileged helper.

## Запуск

```bash
cd /home/book/mail-gateway-admin
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Откройте <http://127.0.0.1:5080>.

По умолчанию приложение только читает `systemctl`, `postqueue` и `postconf`. Оно не изменяет конфигурацию Postfix, не запускает shell-команды из HTTP-запросов и слушает только loopback.

## Переменные запуска

- `MAIL_GATEWAY_HOST` — адрес прослушивания, по умолчанию `127.0.0.1`.
- `MAIL_GATEWAY_PORT` — порт, по умолчанию `5080`.

Не публикуйте приложение наружу до добавления аутентификации, CSRF-защиты, TLS и отдельного privileged helper.

## Разделы

- **Обзор** — состояние Postfix/Dovecot/Rspamd и очередь.
- **Домены** — добавление и удаление доменов, суммарная квота.
- **Почтовые ящики** — добавление и удаление адресов, квота ящика.
- **Журнал** — аудит операций панели.
- **Логи** — последние записи systemd journal для разрешённых сервисов.
- **Безопасность** — состояние и настройка TOTP 2FA.
- **Пользователи** — добавление операторов, администраторов и наблюдателей.
- **Диагностика** — DNS-проверки домена и SMTP connectivity/STARTTLS.
- **Настройки** — редактируемые hostname, домен, relay-режим, TLS и trusted networks.
- **Клиентский портал** — `/client/login`, вход адресом ящика и одноразово выданным паролем.

## PostgreSQL

Приложение использует PostgreSQL 17. Локальная development-база запускается контейнером `mailroom-postgres` на порту `5433`. DSN хранится в `.db-url` с правами `600`; пароль базы — в `.db-password` с правами `600`.

Для другой среды задайте:

```bash
export MAILROOM_DATABASE_URL='postgresql://user:password@db.example:5432/mailroom'
```

## Безопасность MVP

- Административные API требуют сессию.
- Пароли хранятся как PBKDF2-HMAC-SHA256 с уникальной солью.
- После пяти неудачных попыток вход блокируется на 15 минут по имени пользователя или IP.
- Для изменяющих запросов используется CSRF-токен.
- Сессия имеет флаги `HttpOnly` и `SameSite=Lax`.
- TOTP использует стандартный 30-секундный код с допуском одного временного шага.
- 2FA не включается автоматически. После правильной проверки логина и пароля сервер запрашивает TOTP только у пользователя, для которого 2FA включена.

При первом запуске файл `.bootstrap-admin` создаётся с правами `600`. После первого входа задайте собственный пароль и включите 2FA в разделе «Безопасность». Секрет 2FA хранится в `.totp-admin` с правами `600`; эти файлы нельзя публиковать или добавлять в Git.

Перед публикацией за reverse proxy необходимо включить HTTPS, выставить `SESSION_COOKIE_SECURE=True`, добавить CSP и HSTS, а также подключить резервные коды 2FA и ротацию сессий.

## Автоматическая настройка почтового шлюза

Профиль установки находится в `setup_profile.json`. Он включает Postfix, Dovecot, Rspamd, Certbot, DNS-утилиты и `swaks`, а также базовые проверки hostname, портов, TLS и конфигурации сервисов.

Сначала всегда выполняйте dry-run:

```bash
python3 setup_runner.py
```

Применение на поддерживаемом Debian 13/Ubuntu выполняется только явно и от root:

```bash
sudo python3 setup_runner.py --apply
```

Runner отказывается применять изменения на неподдерживаемой ОС, не использует shell и не подставляет произвольные значения в команды. В веб-интерфейсе раздел «Установка» показывает тот же план. На ALT Linux текущий проект намеренно заблокирует применение: сначала нужен отдельный профиль пакетов и служб ALT, а не попытка выполнить Debian-команды.

Изменения доменов, ящиков и настроек записываются в PostgreSQL. Генерация карт Postfix/Dovecot и их безопасное применение выполняются отдельным слоем reconciliation через валидатор и ограниченный privileged helper.
