# Промт: клиентский веб-интерфейс почты Mailroom

Промт для разработчика или ИИ-агента. Его можно передать целиком: в нём есть всё, что нужно знать о системе, требования к интерфейсу и критерии приёмки.

---

## Роль и задача

Ты — senior full-stack разработчик. Сделай для почтовой системы **Mailroom** клиентский веб-интерфейс — веб-почту для владельцев ящиков. Пользователь входит адресом и паролем ящика, читает и отправляет письма, управляет папками, автоответом, переадресацией и фильтрами, меняет пароль. Интерфейс встроен в существующее приложение Mailroom, а не устанавливается как отдельный продукт (Roundcube и т. п. не использовать).

## Контекст системы

- **Сервер**: Debian 13, Postfix 3.10, Dovecot 2.4, Rspamd, PostgreSQL 17.
- **Приложение**: Flask 3 + gunicorn, Python 3.13, psycopg2, passlib. Фронтенд — без сборщика и фреймворков: Jinja-шаблоны и ванильный JS (ES2020). Новые Python-зависимости — только из пакетов Debian 13.
- **Данные ящиков** хранятся в PostgreSQL Mailroom (таблицы `domains`, `mailboxes`, `aliases`). Postfix и Dovecot читают их напрямую через SQL-представления. Хеши паролей ящиков — `SHA512-CRYPT` (`$6$…`, passlib).
- **Письма** лежат в Maildir у Dovecot (`/var/vmail/<домен>/<ящик>/Maildir`); приложение к файлам доступа не имеет и работает только по протоколам:
  - **IMAP** на `127.0.0.1:143` (локальное подключение Dovecot считает защищённым). Вход — через **мастер-пользователя** Dovecot: логин `адрес*mailroom`, мастер-пароль из окружения `MAILROOM_IMAP_MASTER_PASSWORD`. Пароль пользователя приложение проверяет само по своей базе и **нигде не хранит**.
  - **ManageSieve** на `127.0.0.1:4190` с тем же мастер-входом — для автоответа, переадресации и фильтров.
  - **SMTP** на `127.0.0.1:25` для отправки. Подпись DKIM ставит Rspamd. Отправитель (envelope и `From:`) принудительно равен адресу вошедшего ящика.
- Специальные папки Dovecot: `INBOX`, `Sent`, `Drafts`, `Trash`, `Junk` (атрибуты SPECIAL-USE), разделитель `/`.

## Функциональные требования

### Вход и сессия
1. Страница входа: адрес и пароль. Ограничение перебора: 5 ошибок за 15 минут на адрес или IP — временная блокировка; сообщение об ошибке не раскрывает, существует ли ящик.
2. Сессия: cookie `HttpOnly`, `Secure`, `SameSite=Lax`, отдельное имя от админ-панели. Простой — 30 минут, максимум — 12 часов. После смены пароля сессия перевыпускается.
3. Все изменяющие запросы — с CSRF-токеном в заголовке `X-CSRF-Token`.
4. Отключённый ящик или домен — вход запрещён, уже открытые сессии завершаются при следующем запросе.

### Папки
5. Список папок со счётчиками непрочитанных и общим количеством; специальные папки первыми, с русскими названиями (Входящие, Отправленные, Черновики, Корзина, Спам), затем пользовательские по алфавиту, с вложенностью.
6. Создание, переименование и удаление своих папок; специальные папки защищены. Имена с кириллицей (IMAP modified UTF-7) работают.

### Список писем
7. Постранично (50 на страницу), новые сверху; отправитель (в «Отправленных» и «Черновиках» — получатель), тема, дата (сегодня — время, иначе дата), размер, признаки «непрочитано», «важное», «есть вложения».
8. Поиск по папке: «везде», «от кого», «тема», «текст»; фильтр «только непрочитанные», «только важные».
9. Выделение нескольких писем: прочитано/непрочитано, важное, переместить, удалить, «Спам» / «Не спам».
10. Удаление переносит письмо в «Корзину»; в «Корзине» удаляет навсегда (с подтверждением). Кнопка «Очистить корзину».

### Чтение письма
11. Заголовки: от, кому, копия, дата, тема. Письмо помечается прочитанным при открытии.
12. **Безопасный показ HTML**: тело письма открывается в `<iframe sandbox>` без `allow-scripts` и `allow-same-origin`, с ответом сервера под строгой CSP (`default-src 'none'; style-src 'unsafe-inline'; img-src data: …`). Внешние картинки по умолчанию заблокированы, кнопка «Показать изображения» разрешает их для этого письма. Встроенные картинки (`cid:`) отдаются из вложений. Ссылки открываются в новой вкладке с `rel="noopener noreferrer"`.
13. Текстовые письма показываются с сохранением переносов; ссылки кликабельны.
14. Вложения: список с размером, скачивание с `Content-Disposition: attachment` и `X-Content-Type-Options: nosniff`.
15. Действия: ответить, ответить всем, переслать, переместить, удалить, «Спам», «Показать исходник» (как text/plain).

### Написание письма
16. Поля: кому, копия, скрытая копия (несколько адресов через запятую, проверка формата), тема, текст. Автодополнение адресов из адресной книги.
17. Вложения до 20 МБ суммарно (лимит Postfix — 25 МБ на письмо с учётом base64).
18. Ответ: `Re:`, цитата исходного письма, заголовки `In-Reply-To` и `References`, флаг `\Answered` на исходном. Пересылка: `Fwd:`, исходный текст, исходные вложения прикладываются.
19. Подпись из настроек добавляется автоматически.
20. Черновики: сохранение в «Черновики» (флаг `\Draft`), открытие черновика для продолжения, удаление старой версии при пересохранении и после отправки.
21. После отправки копия кладётся в «Отправленные»; адреса получателей добавляются в адресную книгу.
22. Ограничение отправки: не более 100 получателей в час на ящик и 50 получателей на письмо — защита от рассылки спама со взломанного ящика.

### Настройки
23. Профиль: отображаемое имя (для заголовка `From:`), подпись.
24. Смена пароля: текущий пароль обязателен, новый — от 12 символов, не равен адресу.
25. Автоответ (Sieve `vacation`): включить/выключить, тема, текст, период с/по, не чаще одного ответа одному адресату в N дней.
26. Переадресация (Sieve `redirect`): адрес, «оставлять копию в ящике».
27. Фильтры: правила «если поле (от кого / кому / тема) содержит значение — переместить в папку / пометить прочитанным / удалить». Правила хранятся в базе и компилируются в один Sieve-скрипт вместе с автоответом и переадресацией; значения экранируются по правилам Sieve.
28. Квота: занято/всего по `GETQUOTAROOT`, предупреждение при заполнении выше 90 %.
29. Параметры подключения почтовых программ (IMAP 993 SSL, SMTP 587 STARTTLS / 465 SSL, логин — полный адрес) и ссылка на скачивание корневого сертификата, если сервер использует собственный CA.
30. Адресная книга: просмотр, добавление, удаление контактов.

### Интерфейс
31. Три колонки на широком экране (папки — список — письмо), на телефоне — по одному экрану с кнопкой «назад». Тёмная тема по `prefers-color-scheme`.
32. Клавиши: `c` — написать, `r` — ответить, `Delete` — удалить, `/` — поиск, `Esc` — закрыть.
33. Все ошибки — понятным русским текстом рядом с действием, без технических трассировок.
34. Весь вывод пользовательских данных — через `textContent` или явное экранирование; `innerHTML` с данными писем запрещён.

## Нефункциональные требования

- **Безопасность**: CSP на всех страницах (`script-src 'self'`, без inline-скриптов), заголовки `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`. Пароль ящика не попадает в URL, логи, журнал аудита и базу. Мастер-пароль IMAP не покидает сервер. Проверка прав на каждый запрос: письмо читается только из IMAP-сессии своего ящика.
- **Производительность**: список писем — один `FETCH` по диапазону UID с `ENVELOPE`, `FLAGS`, `RFC822.SIZE`, `BODYSTRUCTURE`; не загружать тела писем для списка. Ответ API списка — до 300 мс на папке в 10 000 писем.
- **Аудит**: вход, неудачный вход, смена пароля, изменение переадресации — в общий журнал Mailroom.
- **Код**: отдельный Flask Blueprint `webmail.py`, IMAP/Sieve-клиенты в `mailcore.py`, без глобального состояния между запросами; IMAP-соединение открывается на запрос и закрывается.

## Критерии приёмки

1. Вход с верным паролем проходит, с неверным — нет; после 5 ошибок — блокировка.
2. Письмо, отправленное из веб-почты на внешний адрес, приходит с подписью DKIM; копия в «Отправленных».
3. Письмо с `<script>`, `onerror=` и внешней картинкой показывается без выполнения скриптов и без запроса к внешнему серверу, пока не нажата «Показать изображения».
4. Папка с кириллическим именем создаётся, переименовывается и удаляется.
5. Автоответ отвечает на письмо извне один раз за период; переадресация с копией доставляет письмо и туда, и в ящик.
6. Смена пароля в веб-почте сразу действует для IMAP и SMTP в почтовой программе.
7. Отключение ящика в админ-панели завершает его веб-сессию при следующем запросе.
8. На телефоне (ширина 375 px) все функции доступны без горизонтальной прокрутки.
